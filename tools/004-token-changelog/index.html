Token-Changelog

Welches Problem es löst

  • Nach einem Library-Update sieht man nicht, was sich geändert hat. Im Figma-Forum wird seit Jahren ein Vorher/Nachher gewünscht, ausdrücklich auch für Variablen. Figma-Forum 8807, Figma-Forum 90022
  • Ob eine Token-Änderung etwas kaputt macht (entfernt, umbenannt, Typ geändert), muss man von Hand aus zwei JSON-Ständen herauslesen. Regeln dafür gibt es, etwa: Entfernen ist ein Major. Spectrum Design Data, Design Tokens (Substack)
  • Adobes token-diff-generator kann das, aber nur auf der Kommandozeile und nur für Spectrum-Tokens mit UUID. Ein Werkzeug im Browser für beliebige Token-Dateien habe ich nicht gefunden.
Belegt am 22.11.2026 (Suchzusammenfassungen), Quellen in meta/probleme.md.

So sieht das Problem aus

Ein Designsystem ändert sich laufend: Eine Farbe bekommt einen neuen Namen, eine andere fällt weg. Wer das System benutzt, erfährt meist nur „es gab ein Update“. Ob danach etwas im eigenen Produkt nicht mehr stimmt, merkt man erst, wenn es kaputt ist. Ein Changelog sagt vorher, was sich ändert und was man tun muss.

Füge den alten und den neuen Stand deiner Tokens ein (DTCG mit $value oder Style Dictionary mit value). Das Tool findet Neues, Entferntes, Umbenanntes, geänderte Werte und Verweise, die ins Leere zeigen, und schlägt die nächste Versionsnummer vor. Alles bleibt in deinem Browser.

Changelog








Tool 004 / 22.11.2026. Einstufung: Major, wenn ein Token entfernt oder umbenannt wird, seinen Typ wechselt oder ein Verweis ins Leere zeigt. Minor bei neuen oder als veraltet markierten Tokens. Patch bei geänderten Werten und Beschreibungen. Umbenennungen werden erkannt, wenn ein entferntes und ein neues Token denselben Wert und Typ haben; bei mehreren Möglichkeiten gewinnt der ähnlichste Name. Das bleibt eine Vermutung, bitte prüfen.
